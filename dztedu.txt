PROJECT: DevZoft Learning
Full-Stack Educational Resource Platform
1. YOUR ROLE

Build a complete, production-ready educational resource platform called DevZoft Learning.
Do not create only a UI prototype, static website, or demonstration. Build a functional application with a real database, authentication, file storage, administrative permissions, and working integrations.

2. PROJECT REQUIREMENTS
Build two applications connected to one backend.
Application A: Android App
• Framework: Flutter
• Language: Dart
• Audience: School and college students
• Purpose: Access free educational resources and learning materials.
Application B: Web Admin CMS
• Framework: Next.js
• Language: TypeScript
• Styling: Tailwind CSS
• Purpose: Manage the entire educational platform from a browser.
Backend
• Platform: Supabase
• Database: PostgreSQL
• Authentication: Supabase Auth
• File storage: Supabase Storage
• Authorization: PostgreSQL Row Level Security
• Server-side operations: Supabase Edge Functions or another appropriate secure server-side mechanism.
Hosting
• Admin CMS: Vercel
• Backend: Supabase
• Source control: GitHub
• Mobile distribution: Android APK and Google Play-compatible release build.
Use stable, mutually compatible dependencies. Check existing project files before choosing package versions.

7. DATABASE SECURITY AND RLS
Security is mandatory.
Enable Row Level Security on all exposed tables containing user data or privileged information.
Implement policies for the following cases:
Public or authenticated students:
• Read only published resources that are available to them.
• Read public curriculum metadata.
• Manage their own bookmarks.
• Manage their own learning history.
• Access their own quiz attempts.
• Read announcements intended for them.
Teachers:
• Manage only the resources and quizzes within their assigned permissions.
Editors and Content Managers:
• Perform authorized content-management operations.
Administrators:
• Perform operations allowed by their permissions.
Super Admin:
• Perform authorized platform-wide operations.
Additional requirements:
• Users must never modify their own privileged role assignments.
• Sensitive administrative actions must use trusted server-side checks.
• Validate role assignments and permission changes.
• Restrict private file downloads.
• Protect against insecure direct object references.
• Validate input on the client and server.
• Use parameterized queries or safe database APIs.
• Rate-limit sensitive operations where appropriate.
• Protect secrets using environment variables.
• Apply least-privilege access.
• Avoid leaking private information in error responses.
Do not treat a hidden UI button as a security boundary.
Create automated or documented tests for important RLS policies.
